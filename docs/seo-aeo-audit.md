# Search, answer-engine and code audit

Scope: the committed static site at `ksa.salaroutsourcing.com` (repo `Salaroutsourcing/ksa`), audited and then fixed in one change set.
Method: rebuild from source, run `tools/check.py` and the Node tests, parse every built page (headings, metadata, JSON-LD), compare pages against each other for duplication, and inspect what the live host actually serves.

## Bugs found (all fixed)

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | High | `article()` never passed `kind` to `save()`, so every guide shipped `og:type="website"` with a page node typed `WebPage` even though an `Article` node existed. | `kind` is forwarded; `og:type`, `article:published_time` and `article:modified_time` follow the page type. |
| 2 | High | Guide `Article` structured data had no `datePublished`, and the editorial date was hard-coded in three places. | One `PUBLISHED` / `UPDATED` constant in `tools/content.py`; both dates emitted in ISO form and on the page. |
| 3 | High | `/problems/degree-passport-name-mismatch/` was generated from the first three sections of `/guides/degree-name-different-from-passport/`: 62% of its main copy was duplicated. `/problems/document-rejected/` and `/problems/previously-rejected/` overlapped 67%, and four problem pages shared identical generic sections. | Every problem page now has its own short answer, description and sections; the reused block is gone. Measured length went from ~360 to ~2,000 words, and no page repeats another page's sections. |
| 4 | High | 14 of the 15 destination guidance paragraphs existed only in `assets/destinations.json`, fetched at runtime: invisible to crawlers and assistants, and Germany/France/Italy were unreachable in the selector. | All destination guidance is rendered as text on `/countries/` and the home page, the selector reads that text, the runtime `fetch` and the JSON file are gone, and the three missing destinations are selectable. |
| 5 | Medium | Meta descriptions were reused card taglines: `/problems/name-mismatch/` shipped `Passport ≠ Degree` (17 characters), `document-rejected` 20, `which-authority` 16, `missing-document` 23. | Card blurbs split from descriptions (`summary` / `tag` fields), every description rewritten to a unique 100-170 characters, enforced by the checker. |
| 6 | Medium | The Organization node had only name, URL, description and email. | Added logo, image, postal address, telephone, contact point (email, phone, Pakistan, English/Urdu), service area, subject areas and same-as links. **Confirm the address, telephone and cross-site links before publishing.** |
| 7 | Medium | `sitemap.xml` had no `lastmod`; the validator only checked sitemap to page, so a page missing from the sitemap passed silently. | `lastmod` is generated; the checker now fails if an indexable page is absent from the sitemap, and vice versa. |
| 8 | Medium | Heading structure jumped `h1` to `h3` on seven pages (card grids, sidebar, hero document title, process tiles), `journey()` put `<p>` inside `<button>`, and `menu-toggle` had no `type`. | Screen-reader-only `h2` headings where a grid follows a page title, the journey label became a `span`, the document title became a paragraph, and every button declares its type. The checker enforces heading order. |
| 9 | Low | Two titles exceeded search-result width, `og:locale` was missing, no feed, no `llms.txt`, robots.txt said nothing about AI crawlers. | Titles shortened, `og:locale` added, `feed.xml`, `llms.txt` and an explicit crawler policy generated by the build. |
| 10 | Low | `tools/check.py` crashed (KeyError, JSON traceback) instead of reporting on a page missing `og:url` or with malformed JSON-LD, and it checked none of the rules above. | Rewritten as a validator with those rules and safe parsing. |

## Not a bug

`tools/build.py` displays `'@context':'https://***@graph'` in some tooling output. The file, the built HTML and the deployed page all contain a valid `https://schema.org` context; the graph parses. It is an output-display artifact.

## Working practices this change set enforces

- Content first: every claim in the pages is conditional and source-linked; no fee, timeline, approval or treaty guarantee is published.
- One topic, one page: no page borrows another page's sections, so near-duplicates cannot be reintroduced accidentally.
- Text before scripts: guidance lives in the HTML; JavaScript only enhances it.
- The build is the source of truth: `python3 tools/build.py && python3 tools/check.py && node --test tools/assessment.test.cjs`, with CI failing on stale output.

## Recommended next steps (not done here)

1. **Confirm and publish the entity details**: office address, telephone and any cross-site `sameAs` links. They are in one dict (`BUSINESS`) in `tools/content.py`. Accurate contact details plus a Google Business Profile with matching name, address and phone are the strongest trust signals still missing.
2. **Citations and profiles**: consistent listings (business directories, chambers, professional networks) give assistants independent confirmation that the business exists and does this work.
3. **Terminology pages**: an Urdu or roman-Urdu page for `مصدقہ` / mosadaqa searches, and city pages (Rawalpindi, Islamabad) for local intent, once real service details can be published.
4. **Independent review**: an author or reviewer entity may only be added when a real, named, verifiable person reviews the content. Nothing invented.
5. **Host caching**: asset responses currently revalidate on every request (`cache-control: public, max-age=0, must-revalidate` behind Cloudflare). A cache rule for `/assets/*` improves repeat-visit speed; the font and stylesheet are the main wins.
6. **Measurement**: once published, watch Search Console coverage, query growth for mosadaqa terms, and whether AI assistants cite the guide pages. Nothing in this change set claims a ranking outcome.
